# Лаба 5 — Хранилища данных в облаке (Block, File, Object: выбор и применение)

## 1. Цель работы

Закрепить на практике знания, полученные в лекции 5 «Хранилища данных в облаке»:

- различать три типа облачных хранилищ — **Block**, **File** и **Object** — и понимать их уровни;
- выбирать и применять сервисы **EBS**, **EFS** и **S3** (и их аналоги у других провайдеров);
- учитывать соотношение производительности и стоимости (IOPS, Throughput, Latency);
- выстраивать грамотную архитектуру хранилищ как микс разных типов;
- применять чек-лист выбора и избегать типичных ошибок.

На выходе вы получаете обоснованную схему хранения данных для вашего сервиса и отчёт по проекту.

## 3. Исходные данные (условие задачи)

Вы — DevOps-инженер сервиса, который вы придумали в [Лабе 1](../lecture-1-introduction/lab.md). Заказчик просит спроектировать архитектуру хранения данных для того же веб-приложения, для которого вы уже спроектировали сеть (Лаба 1).

Требования заказчика:

| **Сервис** | **Назначение** | **Особенности хранения** |
| --- | --- | --- |
| Веб-фронтенд | Публичный сайт + статика | Статика (изображения, стили, скрипты) раздаётся через CDN, возможны всплески трафика |
| API-бэкенд | Бизнес-логика сервиса | Выполняется на виртуальных машинах, нужен быстрый системный диск |
| База данных | Хранение основных данных сервиса | Высокая нагрузка, критична предсказуемая задержка (IOPS), нужны снапшоты |
| Общий каталог | Контент для нескольких серверов | Несколько серверов должны видеть один каталог одновременно |
| Бэкапы и архив | Резервные копии на петабайты | Многолетнее хранение с минимальной стоимостью, защита от случайного удаления |

Требования к отказоустойчивости и экономии:

- каждый тип данных хранится в подходящем по классу хранилище — никакой переплаты;
- не должно быть Single Point of Failure: бэкапы и снапшоты должны позволять восстановление в любой зоне;
- статика и архивы должны дешеветь по мере «остывания» данных (жизненный цикл).

## 4. Задание и ход выполнения

### Этап 1. Три типа хранилищ и сравнительный анализ

- Сформулируйте закономерность: как меняются производительность и стоимость от Block к Object.
- Заполните таблицу аналогов EBS, EFS и S3 у провайдеров Yandex Cloud, VK Cloud, Azure, Google Cloud.

**Контрольная точка 1**: каждому сервису соответствует правильный тип хранилища, в системе нет лишней переплаты.

### Этап 2. Сервисы AWS: EBS, EFS, S3

- Для базы данных выберите тип тома EBS и обоснуйте выбор: **gp3** (базовый), **io2/io1** (provisioned IOPS), **st1/sc1** (дешёвые HDD) — что и когда брать.
- Спланируйте снапшоты томов для аварийного восстановления. Укажите, где хранится снапшот EBS — в зоне доступности или в регионе — и почему это важно для восстановления в любой зоне.
- Для веб-фронтенда настройте объектное хранилище под статику и CDN.
- Для общего каталога выберите файловое хранилище и опишите, как несколько серверов монтируют его одновременно (протокол, общая шара).
- Для бэкапов и архива определите классы хранения и правила жизненного цикла (переход объекта между классами по частоте доступа).

💡 *Подсказка из лекции: «Блок — для скорости, Файл — для общего доступа, Объект — для масштаба и денег».*

**Контрольная точка 2**: БД не лежит в объектном хранилище, общий каталог не сделан на блочном диске, архивы дешевеют по жизненному циклу.

### Этап 3. Классы хранения и жизненный цикл в S3

- Заполните таблицу классов хранения S3 от «горячего» к «холодному» (Standard, Intelligent-Tiering, Standard-IA, Glacier, Glacier Deep Archive): назначение, скорость доступа, стоимость.
- Сформулируйте правило жизненного цикла для бэкапов: через сколько дней объект переносится в Standard-IA, через сколько — в Glacier. Обоснуйте экономию.
- Опишите, как работают S3 Select и Glacier Select (SQL-запросы внутри объекта) и зачем они нужны.
- Включите версионирование для бакета с бэкапами и объясните, от чего оно защищает.

**Контрольная точка 3**: правило жизненного цикла описано корректно, версионирование обосновано.

### Этап 4. Архитектура и безопасность хранилищ

- Составьте итоговую схему хранения данных для вашего сервиса (блок-схему).
- Пройдитесь по чек-листу из 6 вопросов выбора хранилища и примените его к каждому типу данных.
- Опишите, как обеспечено резервирование: где живут снапшоты EBS, в скольких зонах лежит EFS, как S3 реплицирует объекты между зонами.

**Контрольная точка 4**: у каждого типа данных определён тип и класс хранилища, резервирование обосновано.
