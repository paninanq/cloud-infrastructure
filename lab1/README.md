# Лаба 1 — Проектирование сетевой архитектуры облака (VPC, балансировщики, связность)

## 1. Цель работы

Закрепить на практике основы сетевой архитектуры облака:

- спроектировать виртуальную частную сеть (VPC) с несколькими зонами доступности;
- выбрать и настроить балансировщик нагрузки под конкретный сервис;
- обеспечить связность подсетей с внешним миром (IGW, NAT);
- применить чек-лист проектирования и избежать типичных ошибок;
- задокументировать получившуюся сеть.

## 3 Исходные данные

**Название сервиса:** *Почини.Онлайн*

**Тип сервиса:** *онлайн-платформа поиска автосервисов и организации ремонта автомобилей (маркетплейс услуг с личными кабинетами клиентов, механиков и автосервисов).*

**Целевая аудитория:** *владельцы автомобилей, механики и автосервисы; на первом этапе — пользователи из России, в том числе из регионов с распределёнными автосервисами.*

**Основные пользовательские сценарии:**

1. Клиент регистрируется или входит по коду из SMS, добавляет автомобиль и ищет подходящий автосервис по расположению, услугам и отзывам.
2. Клиент просматривает профиль автосервиса, создаёт заявку на обслуживание, согласует детали и переписывается с представителем автосервиса.
3. Механик или автосервис управляет профилем, услугами, публикациями и заявками, а также отвечает клиентам в чате.
4. Пользователь загружает фотографии и документы автомобиля, получает push-уведомления о сообщениях и изменениях статуса заявки.

**Состав сервисов:**

| **Сервис** | **Назначение** | **Особенности (что важно знать для проектирования)** |
| --- | --- | --- |
| Веб-клиент | Публичный интерфейс `pochini.online` для клиентов, механиков и автосервисов | HTTPS; отдаёт статические файлы; доступен из интернета |
| Backoffice | Внутренний интерфейс операторов на `admin.pochini.online` | HTTPS только из административной сети/VPN; не должен быть доступен из общего интернета |
| Admin | Внутренний BFF для Backoffice: операторские сессии, RBAC и moderation API | Принимает запросы только от Backoffice через административную сеть/VPN |
| API Gateway | Единственная публичная точка входа в backend и BFF для фронтенда | HTTPS REST `/api/v1/**` и WebSocket `/api/v1/ws`; проверка сессий и маршрутизация к внутренним сервисам |
| User-ID | Аутентификация, сессии и авторизация пользователей | Внутренний HTTP API `/user-id/api/v1` и `/user-id/internal/v1`|
| Products | Доменные данные платформы: профили автосервисов, автомобили, заявки, услуги, публикации и отзывы | Внутренний HTTP API `/products/api/v1` и moderation API |
| Chats | Чаты между клиентами и автосервисами, включая realtime-обмен сообщениями | Внутренний HTTP/WebSocket API `/chats/api/v1`|
| Search | Поиск автосервисов, услуг и связанных объектов | Внутренний API `/search/api/v1`|
| Media | Загрузка и выдача фотографий/файлов через S3-совместимое хранилище | API `/media/api/v1`; бинарные данные передаются по presigned URL; Медиафайлы передаются между клиентом и S3-совместимым хранилищем
напрямую через публичный HTTPS-endpoint.|
| Notifier | Коды подтверждения, SMS/звонки, email и push-уведомления | Внутренние API `/notifier/api/v1` и `/notifier/internal/v1`; исходящие соединения к SMTP, SMS-провайдерам и Expo Push API |
| PostgreSQL | Надёжное хранение пользователей, профилей, заявок, чатов и уведомлений | Приватная подсеть; вход только от backend-сервисов; без публичного IP; резервное копирование в S3-совместимое хранилище |
| Redis | Кэш, rate limiting, blacklist сессий и служебное состояние realtime-сервисов | Приватная подсеть; вход только от разрешённых сервисов; без публикации наружу |
| RabbitMQ | Асинхронная доставка событий между backend-сервисами, например уведомлений | Приватная подсеть; AMQP доступен только сервисам-продюсерам и консьюмерам; management-интерфейс не публикуется |
| MinIO | Хранение медиафайлов и резервных копий | Приватная подсеть; доступ через Media/presigned URL и административную VPN-сеть; публичные bucket'ы не используются |
